本轮新增了可重复运行的诊断组件和命令行入口，并对现有四个检查点执行了
12 组真实采样。没有新增训练、修改奖励、更新源模型或改变覆盖记忆的默认开关。
目的在于缩小上一轮失败试训的排查范围，尚未完成有效协作策略的训练。

## 实现范围

| 文件 | 功能与中文说明 |
|---|---|
| `training/diagnostics.py` | 复用 GAE、价值损失与第一轮 PPO 目标，计算共享梯度；统计覆盖模式、动作幅度与趋同程度；解释参数、返回值、无定义指标和诊断局限 |
| `scripts/diagnose_training.py` | 从同一份模型/配置源字节加载并记录 SHA-256；核对输入版本、优化配置和实际环境；独立种子采样，向新目录写报告 |
| `tests/test_training_diagnostics.py` | 10 项手算、零梯度、输入敏感性、只读性、概率错配、真实 CLI、重复运行和拒绝覆盖测试 |
| `README.md`、本文 | 入口、真实诊断数据、限制和下一步方向 |

沿用现有 NumPy、PyTorch，没有新增依赖。普通训练与评估命令保持原行为。
诊断函数使用 `autograd.grad`，不调用 `optimizer.step` 或写入参数的 `.grad`。
命令行会新建模型与环境，采样会推进这个新环境；原检查点和既有实验不变。

## 指标含义

1. **更新前概率误差**：对刚采样的动作重新计算 log-probability，检查
   `exp(new_log_prob-old_log_prob)` 偏离 1 的最大绝对误差。大偏差可能导致 PPO
   在首次更新前就错误裁剪。它检验概率重算，不直接衡量任务能力。
2. **共享梯度**：按原更新器的第一轮目标，分别计算 Actor 与
   `value_coef × value_loss` 对同一编码器参数集合的梯度范数及余弦相似度。
   未参与运算的参数按零贡献处理；Actor 梯度为零时比值为空，任一梯度为零时
   余弦为空。比较不含熵项，是裁剪全局梯度之前的信号，也不是 Adam 的实际步长。
3. **覆盖模式**：统计观测中的 9 位本机历史模式，并在相同地图掩码内检查是否
   存在不同历史；覆盖比例只在地图有效格上计算，不能当作完整地图已搜索面积。
4. **历史输入敏感性**：在观测副本中清零 9 个覆盖标志，保留 9 位有效掩码、
   原任务特征及邻居输入，再比较确定性动作的平均/最大分量绝对变化。
   该输入可能离开训练分布，差值不表示记忆的任务收益或唯一因果贡献。
5. **动作幅度与趋同**：确定性动作的平均二维向量范数，以及同一步在线智能体
   动作相对均值的均方根距离。后者更小表示这批观测上的动作更相似，不等于
   智能体位置已聚集。另记录绝对值达到 0.99 的动作分量比例，检查输出饱和。

采样按随机策略执行，动作描述和输入消融按确定性策略计算。所有统计都只针对
这些采样观测；不同模型产生不同轨迹，不能将它们当作同一状态集上的因果对照。

## 实际协议与结果

四个检查点均来自前两轮种子 0 的 Huber 试训，训练后模型均为 25,600 环境步：

- 无记忆初始及训练后：`outputs/training_stability_huber_20261024/`。
- 有记忆初始及训练后：`outputs/coverage_memory_pilot_20261025/`。

每个模型单独使用诊断种子 **30000、30001、30002**，每个种子采集 **256 步**，
合计 **3,072 环境步**。每组节点数、地图、目标、故障和通信采用该模型原训练
配置，不执行参数更新。它们是三个诊断轨迹种子，不能视为三个独立训练种子。

下面是三个诊断轨迹上的最小值到最大值，不是置信区间或跨训练种子误差范围。

| 检查点 | 加权 Critic/Actor 梯度范数比 | 平均动作范数 | 同一步动作差异 RMS |
|---|---:|---:|---:|
| 初始无记忆 | 2.512–4.324 | 0.12960–0.13783 | 0.02609–0.02868 |
| 初始有记忆 | 2.524–4.348 | 0.12960–0.13783 | 0.02609–0.02868 |
| 训练后无记忆 | 0.492–2.284 | 0.25230–0.26542 | 0.04517–0.04661 |
| 训练后有记忆 | 0.870–1.700 | 0.52839–0.53514 | 0.01049–0.01912 |

初始模型的共同参数相同、新输入列为零，因此初始动作描述相同。扩展后的
编码器有新增可训练参数，其梯度范数允许不同，不能要求两个初始梯度也完全相同。

其余真实结果：

- 12 组最大更新前概率比误差为 **7.6294×10⁻⁶**，未发现本批样本中的明显重算错配。
- 有记忆初始模型各出现 **31、34、35** 种历史模式；训练后为 **27、32、33** 种。
  这排除了本批样本中“覆盖输入始终为一个常量”的简单解释。
- 初始有记忆模型清零历史的动作变化为 0，符合新增列零权重初始化。
- 训练后有记忆模型，清零历史的平均分量绝对变化分别为
  **0.004676、0.005972、0.005319**，最大变化为
  **0.011544、0.019731、0.018549**。历史已影响动作，但收益仍需任务对照证明。
- 有记忆训练后共享梯度余弦分别为 **0.00509、-0.12524、-0.02553**。
  本批不支持“Critic 在所有阶段都以很大梯度压制 Actor”的结论。
- 四种模型在这批观测上的动作饱和分量比例均为 0，未出现绝对值接近 1 的分量。

有记忆模型在采样状态上的确定性动作幅度更大、智能体之间动作差异更小；结合
上一轮评估中更高的碰撞计数，应进一步核对动作趋同、边界截断与位置聚集的
时间关系。现在只能将其列为后续排查方向，没有证明它是退化的唯一原因。

## 命令

在项目目录使用已安装依赖的 Python，选择尚不存在的输出目录：

```powershell
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:PYTHONUTF8 = '1'

# 本轮仅采样诊断，不训练模型；其余种子改为 30001/30002，并更换输出路径。
python scripts/diagnose_training.py --checkpoint outputs/coverage_memory_pilot_20261025/training/mappo_checkpoint.pt --run-config outputs/coverage_memory_pilot_20261025/training/run_config.json --seed 30000 --rollout-steps 256 --output-dir outputs/coverage_diagnostic_review/seed_30000

# 使用同一训练配置可诊断对应初始模型，将 checkpoint 改为 initial/ 下的文件。
# 无记忆检查点与配置均改为 training_stability_huber_20261024 下对应文件。
python -m unittest tests.test_training_diagnostics -v
python -m unittest discover -s tests -q
```
